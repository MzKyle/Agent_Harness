# 后续方向（未实现）

## M2：可信验证和能力反馈

在明确授权的临时工作区执行批准的测试命令，记录提交/环境/结果，验证后晋升命令状态；
为 feature-planning 的结构化计划增加验收执行器和可复用能力缺口报告。
先做原生 Linux CI 与真实认证环境中的 DSH/Codex 验收。
进一步评估配置来源签名、并发路径替换保护，以及依赖更新策略。

## M3：项目观测适配

按真实需求接入脱敏日志查询、FastAPI 状态、React/Electron UI 测试、WPF 诊断。
优先复用现有机制，再补必要的观察接口；评估 C++/ROS 2 识别。
真实设备和 GPU 操作需单独权限和验收，不默认加入通用工具权限。

## M4：知识与评估闭环

在版本/证据契约稳定后实现受控长期知识检索、知识晋升审查和回归评估。
只有检索规模证明需要时才评估索引或向量库。
保持可替换 Runtime Adapter；不自动扩展为云上传、多用户平台或远程调度系统。
