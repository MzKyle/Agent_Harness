# 授权与运行限制

本项目实际工具边界是只读、限量的项目元数据：

- CLI 路径必须由用户显式提供；MCP 仅接受进程预授权根的不可扩展 ID。
- 路径先规范化，拒绝词法越界；扫描不跟随链接/junction，读取前后检查规范路径。
- 扫描排除 .git、node_modules、环境/凭据、日志、数据/模型/缓存等目录；不读取其内容。
- 配置严格校验，工具结果显式投影、通用错误码；从不输出原始脚本、原始 stderr、环境值或日志正文。
- MCP 工具不注册写入、执行、网络或硬件能力。DSH 模型工具也仅暴露 MCP 和 Skills loader。
- DSH 遥测默认关闭；不自动清 Docker、数据库、数据集，不推送/合并，不修改目标主分支。
- Codex 是可选配置，默认不启用。本项目不会自动改变原生 Codex 全局设置或权限。

边界不覆盖被用户授予的原始项目路径名称是否适合发送给模型：目录名、组件名和框架仍是元数据，
对敏感项目应先审阅 inspect 输出。常见 Token 形状会脱敏，任意秘密若被人为伪装成普通名称，
无法用通用正则可靠判定。不要将秘密填入项目名称或配置路径。

同一账户的并发恶意进程仍可能在检查与实际打开之间替换目录，Node 的跨平台文件 API
不能提供完整的 dirfd/openat 隔离。链接检查是纵深防护，不是操作系统安全沙箱。
运行不受信任工程应使用独立账户/一次性 VM、最少文件挂载和网络规则。
DSH 的 JS YAML、插件和原生凭据系统是可信运行配置；不要加载未经审阅的外部 Profile/patch。
DSH 官方明确说明尚未经过安全审计，不能将其沙箱视为绝对隔离。

`runtime run` 是显式在线模型操作；它会发送任务和工具返回元数据。
默认 MCP 不能读取原始业务内容，因此不会自动上传图片、数据库或原始日志。
运行时认证和上游本身的文件/网络行为仍应在受控环境中验收。
