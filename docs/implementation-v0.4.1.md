## 实现范围

认证上下文、附件配置和单次运行配置拆分；签名绑定项目/Task/Workspace，完整覆盖配置而非复用
旧项目参数。新认证物理独立，已授权旧登录仅显式引用。官方 Skill 实际路径枚举驱动开关验证，
公开 Skill 由官方工作区发现机制加载；不实现新 Agent loop、模型客户端或 Skill loader。

Work 生命周期、工程结果和证据有效性分开，最终版本的所有批准命令及原源完整性共同决定
verified。未完成事项即使有有效代码证据也保持 incomplete。签名 Journal、幂等事件、实际进程
退出恢复、Evidence 索引对账和旧 lease 撤销，使恢复不重建旧权限。

Fast/Engineering/Deep/静态 Auto 裁剪服务端工具集合和字节预算；Fast 不加载完整画像/Skill，
有限源码缓存按 Task/项目/内容版本失效。保留真实 usage、工具分类、上下文大小、测试和干预指标。
日常 use/status/latest/resume/doctor 复用既有组件；不自动采集普通 IDE 私有历史。

Hooks 安装、启用、发现、信任、回调交付分别表达。命令固定，签名执行会话 binding 拒绝迟到
回调；官方精确定义信任不能绕过。没有 Hooks 时显式 Work、Exec JSON、MCP 回执仍可工作。

回执/事件/事实历史分片保留，摘要达到便携容量时保留本机签名副本；显式预览归档，Evidence
原始输出不静默删除。删除记忆清理活跃与归档 Work 的候选引用，删除 Work 防止报告重建摘要。
另以独立本地模拟审查复现了21条进展挤掉旧待办的问题；最终容量保护在写Journal/候选前拒绝
超过20条决策或未解决事项，原记录保留，其他Work可继续。该边界另经回归，测量候选与最终
编译文件的差异单列于签名汇总，不把冻结的42次数据冒称为后续二进制的逐字节相同测量。
Work查询另改为全量签名核对后先按项目筛选，再验证所选项目的源码/Evidence，保留归档回退；
相关测试证明不动态读取其他项目，同时仍拒绝被篡改的签名记录。本地查询另测三轮交替延迟，
不把这类服务端API测量等同于端到端模型耗时；Work优化对应work-sessions.js。

异步诊断新增时钟、来源、时间戳、传播期限和重复采样，区分瞬态、持久、陈旧、非法转移、Worker
错误及证据不足。历史快照的当前查询视图重新分析，保留原签名记录不变；缺时钟不沿用旧误判，
另有真实隔离命令和历史格式兼容回归。此修复对应最终第二个差异文件runtime-diagnostics.js。
ALS 只读语义复核、补丁 check 和独立最小 Python/fake 环境为 V0.5 做准备。

## 14 项交付回答

1. **认证和配置隔离**：新建和复用均分离；exec 忽略用户配置并传完整 overrides，官方发现验证
   实际 MCP/Skill。官方认证目录内部缓存/状态仍可能共用，不承诺完全物理隔离。
   Hook文件是官方额外合并层，旧认证HOME存在hooks.json时拒绝启用；空新HOME定义隔离另验。
2. **多附件串扰**：真实 A→B→A 查询核对项目及上下文，跨项目源码/Work 均拒绝；同认证并发
   模型执行明确锁拒绝。不同用户环境、客户端和任意插件组合未作普遍证明。
3. **Hooks 真回调**：按实际事件报告，见 [兼容性记录](hooks-compatibility.md)。配置存在、受管
   Exec 事件和模拟的单元事件均不能算真回调；未信任时 blocked/交付 unobserved。
   旧认证HOME的文件合并问题已实际定位并阻止；新认证尚需用户官方登录与定义审查，不搬旧凭据。
4. **无 Hooks 使用**：已由真实受管运行验证。普通未绑定 IDE 聊天不会自动获得记录功能。
5. **虚假成功**：无测试、异常退出、旧版本通过、缺命令、输出截断、原源漂移和 unresolved
   outstanding 均不能成为当前工程 verified；历史失败与通过证据分别保留。
6. **崩溃恢复**：实际终止专用子进程、签名 Journal 重放和存储故障注入通过；未知/活 PID 锁
   不自动删，已知子进程仍活着时认证锁不释放，恢复不还原执行、分享或源写权限。
7. **Fast/Auto 开销**：按最终多轮独立对照逐类回答，见 [性能](performance-v0.4.1.md)。
   静态分类没有模型调用，不能由工具目录变短直接推断总 Token 或速度收益。
   本版候选单模块两轮：Fast相对Engineering耗时中位数少33.6%、调用少30%、官方input少33.3%；
   相同样本Baseline仍更快，未证明所有任务或真实ALS总体提速。
8. **Deep 信息**：实际 runtime 失败观察、源码、持久状态及错误时间线可查询；诊断为受控命令
   的定点观察，不是生产真实状态证明。额外能力不等于每任务必须调用所有工具。
9. **官方 Codex 使用 Harness**：真实官方 exec 调用标准 MCP，签名回执和独立 Grader 核验；
   发现工具与实际使用分别验收。代码修改仅在专用过滤模拟 Workspace。
10. **跨会话准确性**：显式 Work 保留已验证内容版本、决策和 pending，resume 新建 Task/lease，
    重新 Plan 与复验；实际结果见 [分层验收](verification.md)，不复用旧权威。
    接续合同与整个Work完成分开：选定pending可解决，新的真实疑点仍须保留incomplete，即使代码
    Evidence有效。协议1的总完成失败保留，协议2逐项验证这一合同，不强制抹去新待办。
11. **正常异步传播**：真实 HTTP/Worker/SQLite 延迟后收敛测试和独立 grader 覆盖正常瞬态；
    没可信时钟/时间戳返回 insufficient-evidence。ALS 真实采样接口和时间策略尚未验收。
12. **ALS/Pollen 只读**：刷新画像/规则、源码查询和能力建议前后有界指纹一致；业务构建/测试、
    原源写入、远程分享均为0。排除大数据的完整逐字节 Hash 不在该保证内。
13. **相对 V0.4 的变化**：保留原版较高开销数据，但本轮实际发现原版 Skill 禁用路径有缺陷，
    加上协议/提示/源码不同，不能形成可信逐项因果比较。最终同版本三策略的多轮结果单独报告。
    本版候选单模块Baseline/Fast/Engineering中位为94.5/100.0/150.7秒、6.5/7/10次MCP；
    官方input为94986/97104/145545，均为两样本描述，非账单。最终本地Work查询另测三轮，
    从10886.1降到458.6毫秒、结果一致；该API测量不等于模型总耗时。42次候选与最终构建范围分开。
14. **真实 ALS 下一步**：需要授权过滤快照中的具体 CPU 测试白名单与完整 lock，审查 pytest
    runner 契约/隔离探针，验证取消/异常/重试/脱敏/传播采样。私有源在线、GPU、CVAT、硬件、
    部署分别需要明确授权和环境；当前补丁未应用，fake Python 测试不代表业务回归通过。
    当前Native运行分享门禁只接受fixture-only；真实项目在线使用还需审查并扩展独立的同意契约，
    不能把业务项目改标fixture来绕过限制。日常use可检查真实项目绑定，不能据此推断已可在线编码。
